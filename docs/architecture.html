ai-server-agent — Architecture

Provider-agnostic AI agent on QNAP NAS, communicating via Telegram

1. Main Loop

Cron fires start.sh --once which loops heartbeats continuously. Each heartbeat: check schedules → poll Telegram → process messages. The singleton lock prevents duplicate instances.

2. Schedule Check — Decision Flow

Each heartbeat checks if any scheduled task is due. Three layers: exact match, previous minute, and the new catch-up for missed windows.

3. The Gap Problem (Before Fix)

The heartbeat is blocked while waiting for AI provider responses. Long responses create gaps where schedule-check doesn't run. If the gap spans the scheduled minute, the task is silently missed.

4. The Catch-Up Fix

Now when a heartbeat finally runs after a gap, the catch-up scans all hours since last_run and detects the missed window.

5. File Map

Fix deployed 2026-04-13: catchup_is_due() in schedule-check.sh scans hours since last_run. If the agent was down or busy when a task was due, the very next heartbeat catches up and runs it. Confirmed: generate-news fired at 22:14 after missing 12:00 — completed successfully.
